# /profile-report: local profile/team resume report

This skill produces a local, browser-viewable report from the harness's profile, resume, template, and artefact state.

The report shell is deterministic and template-based (`templates/profile-report/report-template.html`). The profile-specific narrative is generated by the agent and passed to the renderer as JSON; facts must come from local source files, metadata, composition JSON, or resolved resume definitions.

## Modes

- **Individual**: write `state/profile/profile-report.html` for the default profile, or `state/profiles/<person-id>/profile-report.html` for team profiles.
- **Team**: write `state/org/team-report.html` when `state/org/team.yaml` exists.

## Sequence

Resolve the repo root first (`references/harness/repo-root.md`).

1. Resolve the requested mode:
   - Default to individual profile mode when the user says "profile report".
   - Use team mode when the user says "team report", "org report", or asks for all profiles.
   - Use `--profile <person-id>` when the user names a team profile.

2. Read the relevant local context before generating narrative:
   - Profile inputs: `<profile-dir>/profile.md`, `cv-source.md`, `resumes.yaml`, `market-confirmations.yaml`.
   - Resume definitions: resolved via `state/org/resume-types.yaml` plus profile overrides.
   - Render artefact metadata: `<profile-dir>/resumes/<resume-id>/metadata.json`.
   - Composition JSON when present: `<profile-dir>/resumes/<resume-id>/*.composition.json`.

3. Generate a temporary JSON file with this shape:

```json
{
  "profile_overview": "Brief source-grounded narrative for the individual profile.",
  "team_overview": "Brief source-grounded narrative for the team report.",
  "resume_notes": {
    "resume-id": {
      "narrative": "What this resume is positioning for and what the generated artefacts show.",
      "risks": ["Stale approval", "Missing provenance"],
      "next_actions": ["Re-render resume", "Approve baseline"]
    }
  },
  "profile_notes": {
    "default": "Optional profile-specific note for default profile.",
    "person-id": "Optional profile-specific note for a team profile."
  }
}
```

Keep this narrative concise. Do not invent career facts or claims. If source support is missing, write the gap as a risk or next action.

4. Run the deterministic renderer:

```bash
npm run profile:report -- --generated <generated-json-path>
npm run profile:report -- --profile <person-id> --generated <generated-json-path>
npm run team:report -- --generated <generated-json-path>
```

The renderer links PDFs/HTML/DOCX/MD/JSON/PNG artefacts by local relative path. It does not render, approve, submit, or mutate pipeline/application state.

## Output

Return the report path and a short status summary:

```text
Report: state/profile/profile-report.html
Resumes: 6
Warnings: applied-ai stale, missing composition for <resume-id>
```

## Boundaries

- Do not submit, email, or approve anything from this skill.
- Do not edit generated resume artefacts.
- Do not add unsupported claims to narrative; source gaps become report warnings or next actions.
